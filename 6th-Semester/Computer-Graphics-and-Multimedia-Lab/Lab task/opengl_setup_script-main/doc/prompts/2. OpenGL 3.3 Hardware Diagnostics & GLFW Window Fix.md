---

### 🔍 Root Causes & How to Fix

#### 1. Missing GPU Drivers / Using "Microsoft Basic Display Adapter" *(Most Common)*
If Windows was reinstalled or GPU drivers were never installed, Windows defaults to Microsoft's software fallback driver which only supports **OpenGL 1.1**.

* **How to Check**:
  1. Press `Win + X` and select **Device Manager** (`devmgmt.msc`).
  2. Expand **Display adapters**.
  3. If it says **"Microsoft Basic Display Adapter"** or has a yellow warning triangle, the dedicated/integrated GPU driver is missing.
* **Fix**:
  Download and install the official graphics drivers for their processor/graphics card from **Intel**, **AMD**, or **NVIDIA**.

---

#### 2. Older Hardware That Does Not Support OpenGL 3.3
Older integrated graphics (such as 2nd Generation Intel Core processors / **Intel HD 2000 / 3000**, or older Celeron/Pentium processors) only support up to **OpenGL 3.1** on Windows.

* **How to Check**:
  Download OpenGL Extensions Viewer (GLView) or GPU-Z to verify the maximum supported OpenGL version on their machine.

The terminal closing abruptly at step `[5/6]` was caused by three classic Windows Batch (`cmd.exe`) syntax parsing issues:

1. **Unescaped `&` Operator**: In batch files, `&` is a command separator. Writing `echo [5/6] Verifying Graphics Hardware & Live OpenGL 3.3 Context...` caused `cmd` to try executing `Live` as an unrecognized command.
2. **Unescaped Parentheses inside `if (...)` blocks**: Strings containing parentheses like `(opengl32.dll)` and `(Exit code: ...)` were interpreted by `cmd.exe` as prematurely closing the outer `if` block, triggering a syntax error (`") was unexpected at this time."`) that instantly killed the process.
3. **Multi-line PowerShell Caret `^` Parsing**: `cmd.exe`'s caret line-continuation combined with internal quotes and pipe `|` characters in the PowerShell block caused a syntax parse failure.
