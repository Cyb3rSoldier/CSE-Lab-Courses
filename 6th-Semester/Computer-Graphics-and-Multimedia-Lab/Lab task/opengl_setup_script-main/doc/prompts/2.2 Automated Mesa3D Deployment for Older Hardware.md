### 1. Why Did This Happen?

1. **Hardware / Driver Limitation (Intel HD Graphics)**:
   * Your friend’s computer has an older integrated GPU (e.g., **Intel HD Graphics 2000 / 3000 / Sandy Bridge / Arrandale**).
   * On Windows, Intel's official drivers for these GPUs only support up to **OpenGL 2.1** or **OpenGL 3.1**.
   * The project’s C++ code requests an **OpenGL 3.3 Core Profile**:
     ```cpp
     glfwWindowHint(GLFW_CONTEXT_VERSION_MAJOR, 3);
     glfwWindowHint(GLFW_CONTEXT_VERSION_MINOR, 3);
     glfwWindowHint(GLFW_OPENGL_PROFILE, GLFW_OPENGL_CORE_PROFILE);
     ```
   * Because the physical GPU driver cannot provide an OpenGL 3.3 Core context, `glfwCreateWindow()` returns `NULL` and prints `"Failed to create GLFW window"`.

2. **Why It Failed in This Specific Folder**:
   * The setup script ([`install_opengl_admin.bat`](file:///c:/Users/.../Documents/GitHub/[personal]/opengl_setup_script/install_opengl_admin.bat)) automatically deploys Mesa3D into the repository's own `sample_projects/` directories.
   * However, `Hello_Tri_One_Triangle_Full_Colored` is a **separate project folder outside the repository** (e.g., downloaded on `D:\Graphics Lab\...`).
   * Its `build/` folder is **missing the Mesa3D software renderer DLLs**. When `main.exe` starts, Windows falls back to `C:\Windows\System32\opengl32.dll` (the legacy Intel GPU driver) instead of Mesa3D.

# Automated Mesa3D Integration for Older Hardware

## Goal
Implement a fully automated background workflow configured via [install_opengl_admin.bat](file:///c:/Users/.../Documents/GitHub/[personal]/opengl_setup_script/install_opengl_admin.bat) so that on older hardware requiring Mesa3D, running `make win` on **any** project folder (inside or outside the repository) automatically copies `opengl32.dll` and `libgallium_wgl.dll` into the project's `./build` folder without requiring any manual file copying by the student/user.

---

## Technical Design & Architecture

### 1. Centralized Mesa3D Storage
When older hardware is detected (or when native OpenGL 3.3 context creation fails), [install_opengl_admin.bat](file:///c:/Users/.../Documents/GitHub/[personal]/opengl_setup_script/install_opengl_admin.bat) will:
* Create a system repository at `C:\msys64\opt\mesa3d\`
* Copy `Dependencies\mesa3d\opengl32.dll` and `Dependencies\mesa3d\libgallium_wgl.dll` into `C:\msys64\opt\mesa3d\`

### 2. Transparent Build-Tool Hook / Auto-Deploy Wrappers
When the user runs `make win`, two tools execute in sequence:
1. `make.exe` parses the Makefile and runs the compilation command:
   `g++.exe -fdiagnostics-color=always -I./include ./src/main.cpp ./src/glad.c -o ./build/main.exe -Llib -lglfw3 -lopengl32 -lgdi32`
2. `make.exe` runs the compiled executable:
   `./build/main.exe`

To guarantee that `./build/` always contains `opengl32.dll` and `libgallium_wgl.dll` before `./build/main.exe` starts:
* We create a lightweight native C++ wrapper for `g++.exe` (backed up as `g++_orig.exe`) and `make.exe` (backed up as `make_orig.exe`).
* The wrapper forwards all CLI arguments directly to the original compiler/make executable.
* If `C:\msys64\opt\mesa3d\opengl32.dll` is present (legacy hardware mode), whenever compilation targets `./build` (or whenever `./build` exists in the project), the wrapper checks if `opengl32.dll` / `libgallium_wgl.dll` are in the destination folder. If missing, it silently copies them in <15ms.
* Zero changes are required to any `Makefile` or student source code.
* On modern hardware (native OpenGL 3.3+ supported), no wrappers are installed and native GPU acceleration is used directly.

### 3. Clean Uninstallation & Restoration
In [uninstall_opengl_admin.bat](file:///c:/Users/.../Documents/GitHub/[personal]/opengl_setup_script/uninstall_opengl_admin.bat), we ensure that:
* Any wrapped binaries (`g++_orig.exe`, `make_orig.exe`) are restored to their original state.
* `C:\msys64\opt\mesa3d` is cleaned up.
