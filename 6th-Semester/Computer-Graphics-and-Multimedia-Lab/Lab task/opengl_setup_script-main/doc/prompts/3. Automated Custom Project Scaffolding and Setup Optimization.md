### User Input

how can I creat custom projects similar to the ones placed in @[sample_projects] ? is there an automated way to create them?

### Assistant Response

To create custom OpenGL projects similar to the sample labs in `sample_projects`, you can follow either a manual template copy approach or use an automated project generator script.

#### 1. Anatomy of an OpenGL Project
Every project follows this structure:
```text
MyProject/
├── build/
│   └── glfw3.dll                # Required at runtime by main.exe
├── include/
│   ├── glad.h                   # GLAD loader header
│   ├── glfw3.h                  # GLFW header
│   └── khrplatform.h            # Khronos platform header
├── lib/
│   └── glfw3.dll                # Linked during g++ compilation (-Llib -lglfw3)
├── src/
│   ├── glad.c                   # GLAD loader implementation
│   └── main.cpp                 # Your custom OpenGL code
└── Makefile                     # Automation for 'make win' / 'make linux'
```

#### 2. Automated Project Creation
We can create a helper script `create_project.bat` to automate creating folders, copying headers/libraries/Makefiles, and generating a starter `main.cpp`.

### User Input

can project folders be created using CMAKE commands?

### Assistant Response

**Yes and no**:
1. **CMake does not have a built-in scaffolding command** like `cargo new` or `npm create`. CMake is a meta-build generator (it generates Makefiles or Visual Studio solutions from a `CMakeLists.txt`), not an initial project templater.
2. Once a `CMakeLists.txt` is written, CMake commands (`cmake -B build` and `cmake --build build`) can automate dependency downloading via `FetchContent` or post-build DLL copying.

---

### User Input

will integrating cmake increase the repository size?

### Assistant Response

**No, integrating CMake will not noticeably increase repository size:**
- `CMakeLists.txt` files are plain text (~1–2 KB).
- Out-of-source build caches in `build/` are ignored in `.gitignore`.
- CMake can actually reduce repo size by allowing all labs to share one centralized set of headers and libraries instead of duplicating ~2.1 MB per lab folder.

### User Input

correct me if I am wrong: `make win` is used to run the projects and the CMake commands are used to generate the project folder?

### Assistant Response

Clarified the distinction:
- **`create_project.bat` (Scaffolding Script)**: Creates the initial project folders & files (`src/`, `include/`, starter `main.cpp`, `Makefile`). Run once when starting a new lab.
- **CMake (Meta-Build Generator)**: Generates build configurations (Makefiles or VS solutions). It does not create initial source code folders from scratch.
- **Make (`make win`) (Build Tool)**: Compiles the C++ code and immediately launches the resulting `.exe`.

### User Input

using Cmake seems to take extra few steps

### Assistant Response

Agreed. For coursework, learning Modern OpenGL, and lab assignments:
- **Current Setup**: 1 command to create (`create_project.bat`) and 1 command to build & run (`make win`).
- **CMake Setup**: Requires `cmake -B build`, `cmake --build build`, and executing `./build/main.exe`.
For individual developers and university graphics labs, the `Makefile` + `create_project.bat` approach offers the fastest feedback loop with minimal cognitive overhead.
