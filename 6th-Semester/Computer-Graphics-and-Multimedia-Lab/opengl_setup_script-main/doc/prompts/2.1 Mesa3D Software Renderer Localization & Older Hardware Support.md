**Mesa3D is not a separate application or background program—it is a drop-in implementation of OpenGL itself.**

Here is how it works under the hood:

---

### 1. OpenGL is an API Specification, Not a Program
* OpenGL is just a set of standard rules and function names (`glClear`, `glDrawArrays`, etc.) defined by the Khronos Group.
* Normally, **GPU manufacturers** (NVIDIA, Intel, AMD) provide the driver that executes those functions on your graphics card.
* **Mesa3D** is an open-source driver that executes those exact same OpenGL functions using your **CPU (software rendering)** instead of the GPU.

---

### 2. How Windows Loads It (Completely Transparent)
Whenever any OpenGL program (like your `main.exe`) starts on Windows, the operating system looks for a file named **`opengl32.dll`** in this order:

1. **First:** Inside the **current folder** where `main.exe` lives (`build/`).
2. **Second:** Inside the system folder (`C:\Windows\System32\opengl32.dll` $\rightarrow$ which redirects to your Intel GPU driver).

When you place Mesa3D's `opengl32.dll` in the `build/` folder:
* Windows loads Mesa3D **instead of** the outdated Intel GPU driver.
* There is no extra software to launch or keep running in the background.

g++.exe -fdiagnostics-color=always -I./include ./src/main.cpp ./src/glad.c -o ./build/main.exe -Llib -lglfw3 -lopengl32 -lgdi32
./build/main.exe

### 🔍 Cause:
1. When Mesa3D initializes on Windows, it probes backends in priority order: Direct3D 12 $\rightarrow$ Zink (Vulkan) $\rightarrow$ LLVMpipe (CPU rasterizer).
2. On legacy hardware lacking Vulkan drivers, Mesa prints `MESA: error: ZINK: failed to load vulkan-1.dll` as an informational check and immediately switches to LLVMpipe (which is why the window renders successfully).

### 🛠️ Permanent Solution:
* Configured `install_opengl_admin.bat` to permanently register `GALLIUM_DRIVER=llvmpipe` in Windows System Environment variables when Mesa3D is deployed.
* Setting `GALLIUM_DRIVER=llvmpipe` instructs Mesa to load the LLVMpipe CPU rasterizer directly, bypassing the Zink/Vulkan probe and completely eliminating the message.
